## 1. 관측 공간(Observation Space) 차이점

**Non-FT 환경**: 총 1052차원
**FT 환경**: 총 1072차원 (+20차원, +1.9% 증가)

**FT 환경에 추가된 관측값:**
- `ati_force` (3D 벡터 × 5 히스토리) = +15차원
  - ATI 센서 로컬 프레임에서 힘 측정
  - **MODIFIED (2025-12-01)**: Outlier rejection (5000N threshold)
  - 정상 범위: 50-2000N 통과
  - 극단적 outlier (5000N+): Previous valid value로 교체
  - EMA 평활화 계수: 0.25

- `ati_force_threshold` (스칼라 × 5 히스토리) = +5차원
  - Randomized threshold: [150, 200]N
  - Episode마다 다른 값으로 학습 → robust policy

**기타 모든 관측값**: 동일 (로봇 관절 위치/속도, 물체 포즈, 촉각 접촉 등)

## 2. 보상 함수(Reward Function) 차이점

**동일한 보상 (양쪽 환경):**
```
good_finger_contact:      +0.5
position_tracking:        +2.0
success:                  +10.0
action_rate:              -0.005
joint_vel:                -0.0001
undesired_contacts:       -0.01
```

**FT 환경 전용 보상:**
```
ati_excessive_force_penalty: -0.005 × ReLU(||force|| - threshold)
  - Threshold: 150-200N (randomized)
  - Weight: -0.005
  - 공식: penalty = ReLU(force_magnitude - threshold)
  - 목적: 충돌/과도한 힘 감지 및 처벌
  - **중요**: Force는 outlier rejection 후 값 사용 (5000N threshold)

ati_force_magnitude: weight=0.0 (Tracking only)
  - Tensorboard 기록용
  - 실제 reward에 영향 없음
  - 목적: Force 값 실시간 모니터링
```

## 개요
Forge는 NVIDIA의 공식 FT sensor 사용 예제 환경
- 로봇: Franka Panda (가벼운 그리퍼)
- 작업: Peg insertion, Gear mesh, Nut thread
- 우리: UR10e + DG5F (무거운 손)

## 1. FT Sensor Observation 비교

| 항목 | Forge | 우리 (UR10e_ATI_DG5F) | 차이 이유 |
|------|-------|---------------------|----------|
| Force Obs 이름 | `ft_force` [3D] | `ati_force` [3D] | 이름만 다름 |
| Outlier Handling | 없음 | **5000N threshold rejection** | 우리만 extreme outlier 방지 |
| Threshold Obs | `force_threshold` [1D] | `ati_force_threshold` [1D] | 동일 |
| EMA Smoothing | 0.25 | 0.25 | ✅ 완전 동일 |
| History | 없음 (현재값만) | 5-step history | 우리가 더 많은 temporal info |
| Total Dims | 4 (3+1) | 20 (15+5) | History 때문 |

**결론**: Forge는 단순, 우리는 더 풍부한 정보 + outlier rejection

## 2. Force Threshold 비교 (핵심 차이!)

| 항목 | Forge | 우리 | 차이 이유 |
|------|-------|------|----------|
| **Threshold Range** | **[5.0, 10.0]N** | **[150.0, 200.0]N** | 로봇 무게 차이 |
| Randomization | Episode마다 | Episode마다 | ✅ 동일 방식 |
| 평균 Threshold | 7.5N | 175N | 23배 차이! |
| 로봇 무게 | Franka ~0.7kg | UR10e+DG5F ~3.5kg | 5배 차이 |
| Static Force | ~7N | ~34N | 중력에 의한 기본 force |

**분석**:
- Forge threshold가 작은 이유: Franka 그리퍼가 가볍고 정밀
- 우리 threshold가 큰 이유: UR10e + DG5F 손이 무거움 (~3.5kg)
- **비율은 적절**: Forge 7.5N / Franka 7N ≈ 1.07
                  우리 175N / UR10e 34N ≈ 5.15
- **결론**: ✅ 로봇 스펙에 맞게 정확히 조정됨

## 3. USD 구조 비교 (중요!)

### Forge USD 구조:
```
force_sensor (Xform, **mesh 없음!**)
  - Type: Xform
  - Mass: 0.01 kg (거의 0)
  - Inertia: (0, 0, 0)  ← 핵심!
  └─ force_sensor_joint (Fixed Joint)
       ├─ Body 0: force_sensor
       └─ Body 1: panda_hand
```

### 우리 USD 구조 (최종 - 2025-12-01):
```
ATI_Axia90_M50 (Xform + RigidBody + **Mesh 있음**)
  - Type: RigidBody with visual mesh
  - Mass: 0.25 kg (25배 더 무거움!)
  - Inertia: mesh-calculated (non-zero)  ← 차이!
  - enabled_self_collisions: False
  └─ ATI_Sensor_Joint (Fixed Joint)
       ├─ Body 0: ATI_Axia90_M50
       └─ Body 1: dg5f_mount (2-3mm 간격)
```

**핵심 차이점**:
1. **Forge force_sensor**:
   - Mass ≈ 0, Inertia = 0 → **Ghost body!**
   - PhysX constraint force ≈ 0
   - `get_link_incoming_joint_force()` 정상 범위 (5-10N)

2. **우리 ATI sensor**:
   - Mass = 0.25kg, Inertia > 0 → **Real physical body**
   - PhysX constraint force 큼 (특히 reset 시)
   - Extreme values 발생 (220,000N) → **Outlier rejection 필수!**

**왜 Forge는 extreme force가 없는가?**
→ Mass/Inertia가 거의 0이라 fixed joint constraint force가 최소화됨!

## 4. PhysX 읽기 방식 비교

**완전 동일**:
```python
# Forge (forge_env.py:96-97)
self.force_sensor_world = self._robot.root_physx_view.get_link_incoming_joint_force()[
    :, self.force_sensor_body_idx
]

# 우리 (observations.py:282-283)
all_forces = robot.root_physx_view.get_link_incoming_joint_force()
force_torque_world = all_forces[:, body_idx, :]  # 실제로는 parent body frame!
```

**중요**: `get_link_incoming_joint_force()` 반환값
- 이름: "world" (misleading!)
- 실제: **Parent body frame** (joint body0 frame)
- UR10e의 경우: ur10e root frame (거의 world와 같음, base 고정)

## 2025-12-01 오후: OUTLIER REJECTION 구현

### 14:00 - reject_force_outliers() 함수 구현
**파일**: utils.py (Line 256-367)
**기능**:
```python
def reject_force_outliers(env, force, threshold=250.0, buffer_key):
    """
    1. Detect outliers: magnitude > threshold
    2. Replace with previous valid value (NOT clamp!)
    3. Update buffer with valid values only
    """
```

**로직**:
- Outlier 감지 → Previous valid value로 교체
- Valid 값만 buffer 업데이트
- Outlier는 buffer 오염 안 시킴

### 14:30 - observations.py 적용
**파일**: observations.py (Line 362-399)
**변경**: Magnitude clamping → Outlier rejection
```python
# Before
scale = torch.clamp(250.0 / (force_mag + 1e-6), max=1.0)
force_local = force_local_raw * scale

# After
force_local = reject_force_outliers(
    env, force_local_raw,
    threshold=250.0,  # 초기값
    buffer_key="_ati_force_valid"
)
```

### 14:45 - rewards.py 적용
**파일**: rewards.py (Line 493-505)
**내용**: Fallback path도 outlier rejection 적용

### 15:00 - 문제 발견: Threshold 너무 낮음!
**현상**: Contact 회피 학습 재발
**원인**:
```
정상 grasp (300N) → 250N 초과 → REJECTED!
→ Previous value (50N) 사용
→ Policy: "힘이 약하다" → Contact 회피
```

**분석**:
- 250N threshold가 **너무 aggressive**
- 정상적인 강한 grasp (300-500N)도 outlier로 판단
- Reward penalty 작동 안 함 (낮은 값으로 교체)

### 16:00 - Threshold 대폭 상향 (최종)
**파일**: observations.py (Line 390), rewards.py (Line 500)
**변경**:
```python
FORCE_OUTLIER_THRESHOLD = 5000.0  # 250 → 5000
```

**Rationale**:
```
Normal grasp (50-500N):     ✓ 통과
Strong contact (500-2000N): ✓ 통과
Abnormal spike (5000N+):    ✗ REJECTED
Extreme outlier (220,000N): ✗ REJECTED
```

**효과**:
- 정상적인 강한 contact 허용 → Policy가 contact 학습 가능
- 극단적인 outlier만 제거 → RL 안정성 확보
- ~0.5% outlier 환경 격리 → Policy corruption 방지

## Tensorboard 주요 메트릭

### 1. ati_force_magnitude
**정상 범위** (Outlier rejection 적용 후):
- Mean: 3-5N (대부분 환경)
- Grasping: 50-500N
- Strong contact: 500-2000N

**모니터링**:
- Mean이 점진적으로 증가 → contact 학습 진행 ✓
- Mean < 5N 계속 유지 → contact 회피 (문제!)
- Rejected count > 50/4096 → USD/Physics 문제

### 2. DEBUG ATI Force 출력 (터미널)
```
[DEBUG ATI Force] [Step XXXXX]
  PhysX_raw_max=XXXX.XN,      # PhysX 원본값
  EMA_max=XXXX.XN,            # Smoothing 후
  FrameTx_max=XXXX.XN,        # Frame 변환 후
  Rejected_max=XXX.XN,        # Outlier rejection 후 (최종)
  mean=XX.XN,                 # 평균값
  rejected=XX/4096,           # Outlier 환경 수
  resets=XX                   # Reset 환경 수
```

**정상 패턴**:
```
PhysX_raw_max: 100-5000N (가끔 spike)
EMA_max: 100-3000N (smoothing)
FrameTx_max: 100-3000N (같음)
Rejected_max: 50-2000N (outlier 제거됨)
mean: 3-50N
rejected: 0-20/4096 (0.5% 이하)
```

**비정상 패턴**:
```
PhysX_raw_max > 100,000N 지속 → USD 문제
rejected > 100/4096 → Threshold 너무 낮음
mean < 5N 고정 → Contact 회피
```

### 3. Episode Reset 시 패턴
```
Step N-1: mean=4N, PhysX_raw=3000N
Step N:   mean=45N, PhysX_raw=55000N, resets=50  ← Reset spike!
Step N+1: mean=20N, PhysX_raw=110000N
Step N+5: mean=10N, PhysX_raw=110000N
Step N+10: mean=5N, PhysX_raw=110000N  ← 안정화
```

**정상**: Reset 직후 일시적 spike → 빠르게 감소
**비정상**: Reset 후에도 계속 높은 값 유지

## 문제 1: Outlier rejection 후에도 contact 회피

**원인**: Threshold가 너무 낮아서 정상 contact도 rejection
**증상**:
- good_finger_contact < 0
- ati_force_magnitude mean < 5N
- rejected count > 50/4096

**해결**:
1. Threshold 상향: 5000N → 10000N
2. 또는 outlier rejection 비활성화 (clamping으로 회귀)
3. Reward balance 재조정

## 문제 2: PhysX_raw_max가 지속적으로 > 100,000N

**원인**: USD 구조 또는 physics parameter 문제
**해결**:
1. USD 파일 재검토 (mesh overlap)
2. Solver iteration 증가
3. Mass/Inertia 감소 시도

## 문제 3: Rejected count가 계속 증가

**원인**:
- Threshold 너무 낮음 (정상 값도 rejection)
- 또는 학습이 강한 contact를 배우는 중 (정상)

**판단**:
- rejected < 5% + contact 학습 중 → 정상
- rejected > 10% + contact 회피 → Threshold 상향
